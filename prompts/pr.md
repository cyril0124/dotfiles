这次要提交的范围：${@:-（未给出）}

如果上面是「未给出」，先问我要提交哪个分支或哪些改动，等我回答后再动手，不要自己挑范围。

范围确定后，把该范围内的改动按 Conventional Commits 提交并 push。提交前先看 `git status`，只 stage 与这次改动相关的文件，临时文件、日志、构建产物和无关修改都不要进提交。

需要新建分支时，分支名用 `tmp/<slug>`。当前分支是 `main` 或 `master` 时不要直接提交，先问我要不要按上面的命名新建分支。不要 force push。

然后写 PR 标题和描述，先给我看一遍，我同意后才用 `gh pr create` 建 PR，最后报出 PR 链接。

仓库有 PR 模板时优先按模板的章节和顺序来写，模板占用的栏目不要删；没有模板才自己组织段落。

PR 描述只写改动内容和行为结果，不写验证过程、测试步骤这类过程性内容。
